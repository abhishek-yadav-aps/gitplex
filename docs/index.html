One workspace for repos that ship together.

Gitplex builds a combined working directory for tightly coupled repositories. The editable view lives in workspace; the real clones stay in .gitplex/repos. You stage once, push in dependency order, and keep local experiments out of published commits.

[ 01 ] /why

Monorepo ergonomics. Polyrepo ownership.

Some stacks need separate repositories for ownership, release, or access boundaries, but developers still need to change them as one product. Gitplex gives you a single generated edit surface without pretending the repositories stopped being independent.

without with Gitplex
jump between cloned repos work in one generated tree
manually update dependency refs push updates in graph order
risk publishing scratch edits publish only staged workspace files
recreate shell context jump with workspace-mode and repo-mode

[ 02 ] /workflow

The working tree has a memory of every repo.

Gitplex keeps a manifest, backing clone state, and generated workspace in sync so the cross-repo edit path stays quick while the publication path stays explicit.

01 INIT

Clone the graph

Read a manifest, clone each repo, map modules into the generated workspace, and create the baseline.

gitplex init manifest.yaml
02 CHANGE

Edit together

Use the workspace for cross-package edits while backing clones remain under Gitplex control.

gitplex status
gitplex doctor
03 BUILD

Check the workspace

Run the Nix-backed build command from the generated workspace, with remote builders disabled.

gitplex build
gitplex true-build
04 PUSH

Publish intentionally

Only staged workspace files are copied back, committed, and pushed through dependency order.

git add app-db app-gateway
gitplex push -m "ship the change"

[ 03 ] /commands

Command surface for cross-repo work.

The CLI covers the day-to-day shape of a coordinated stack: branch, checkout, rebase, cherry-pick, stash, amend, build, diagnose, and push. 

$ gitplex branch feature/new-flow
$ gitplex checkout release/main
$ gitplex rebase app-gateway release/main
$ gitplex cherrypick app-db abc1234
$ gitplex amend --message "tighten schema wiring"
$ eval "$(gitplex shell-init)"
$ gitplex workspace-mode
/Users/you/project/workspace

$ gitplex repo-mode app-gateway
/Users/you/project/.gitplex/repos/app-gateway
$ gitplex build
nix build --refresh github:srid/devour-flake#default \
  --override-input flake . \
  --option builders ''

$ gitplex true-build
# same build, plus --option substitute false

[ 04 ] /safety

Designed around the scary parts.

Multi-repo tooling is only useful when it protects the work you did not mean to touch. Gitplex treats generated files, backing clones, and staged intent as separate states.

STAGED ONLY

Push what you selected

Unstaged workspace edits are left alone, and a final refresh is skipped when it would overwrite local work.

DIRTY CHECKS

Refuse risky rewrites

Checkout, rebase, and workspace regeneration stop when the workspace or selected backing repos are dirty.

DEPENDENCIES

Update refs downstream

When dependency repos move, downstream flake inputs and locks can be updated before their commits.

BACKING CLONES

Keep escape hatches

Every real repo remains available under .gitplex/repos for inspection, recovery, and manual diagnosis.
